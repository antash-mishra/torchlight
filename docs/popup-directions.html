Making the popup feel at home on Linux

The popup today reads like a terminal: monospace everywhere, // and / prompts, an underscore cursor and fixed graphite colors. Below are three directions, each drawn at real popup size with the real results your index returns for set.

Pick

Direction A, with motion. Try the live prototype first: type in it, use the arrow keys and press Enter. Every effect can be switched off to compare, and slow motion lets you inspect each one. The comparison that led to A is further down.

Nothing waits

Typing, results and launches never wait for an animation. Only the final hide is delayed, by at most 200 ms.

Nothing loops

The spinner runs only while a search is pending, and the sweep plays once per open. The popup stays idle when you're not using it, like the caret blink does today.

Off means off

Turning off animations in the desktop settings (gtk-enable-animations) disables all of it through the existing quiet-motion class. The window itself never animates its size, because on X11 that would redraw the whole window every frame.

Today

As it renders on this machine, from ui/gtk/quiet-system.css
  • The fonts it asks for aren't installedThe stylesheet asks for JetBrains Mono and Space Grotesk. Neither is installed here, so GTK falls back to DejaVu Sans Mono and Noto Sans. The design approved in ADR 0027 never actually renders.
  • Two rows, same pathThe two set headers differ only by NDK version (27.0.12077973 and 27.1.12297006). Path shortening drops leading folders first, so both rows show the same text (dashed outline).
  • Every file gets the same iconEvery file uses text-x-generic-symbolic, so a Go source file, a C header and a PDF all look the same at a glance.
  • Hard-coded colors33 hex values (9 distinct colors) ignore Mint-Y-Dark's palette and accent, and stay dark on a light desktop.
  • Terminal vocabulary at 10–11 pxHints like ctrl ↵ reveal and labels like app and file are easy to read if you built it, but confusing for anyone else.
A

Blend in with Mint-Y

Looks like the GNOME Shell search or the Cinnamon menu search

What changes

  • Colors come from the theme's named colors, so light mode, dark mode and the accent follow the desktop.
  • No font-family: the popup uses the desktop font.
  • A search icon in the entry and the native text cursor.
  • Full-color file-type and app icons at 32 px.
  • Key hints drawn as keycaps, using desktop wording.

Code

  • quiet-system.css uses @theme_bg_color, @theme_fg_color, @theme_selected_bg_color and @borders. It ends up shorter.
  • gtk_entry_set_icon_from_icon_name(…, GTK_ENTRY_ICON_PRIMARY, "system-search-symbolic") on the existing GtkEntry.
  • Delete the caret overlay, draw_caret and both blink timers in view.c.

Trade-offs

  • It looks like the rest of your desktop, so Torchlight loses a visual identity of its own.
  • Your Cinnamon interface font is set to Noto Mono 13, so on your machine A would render in mono. The mockup uses Mint's default, Noto Sans.
  • GTK4 only themes this because Mint-Y ships a gtk-4.0 folder. It does, so it works on your setup.
B

Keep the look, fix the type

Torchlight's own graphite and moss, with Linux-native typography

What changes

  • Keeps the palette and the underscore cursor you chose in ADR 0027.
  • Ubuntu Sans for the query and names, and Ubuntu Sans Mono only for paths. Both ship with Mint.
  • A moss search icon replaces // and /, and the wordmark moves to a quiet corner.
  • A Type column (Folder, Go source code, Settings) replaces file, app and folder.
  • The part of each name that matched the query is highlighted.

Code

  • Font and size changes in the CSS, plus label and icon changes in view.c.
  • Type text from g_content_type_get_description.
  • Highlight with a PangoAttrList on the name label. Exact substrings are easy to find in the UI. Fuzzy and typo matches need the daemon to send match spans, which is a protocol change.

Trade-offs

  • Distinctive, and closer to what you already approved.
  • Still ignores light themes and accent changes. Switch the toolbar to Mint-Y Light to see a dark popup on a light desktop.
C

Command palette

A's styling, with more structure, like KRunner or Raycast

What changes

  • Results are grouped by kind. Groups are ordered by their best-ranked result, so the ranking still decides what comes first.
  • A detail pane for the selected result: type, size, date, full path and a text preview.
  • Tab shows actions: Open With…, Copy Path, Open Terminal Here.
  • Scope chips to narrow the results to Apps, Folders or Files.

Code

  • Section headers via gtk_list_box_set_header_func.
  • The pane uses g_file_query_info_async and an async read of the first few KB, inside the popup only. The daemon query path stays free of I/O.
  • Scopes need a kind filter in the query protocol, because the popup only requests ten rows.
  • Each new action needs resolve-path tests, like Open and Reveal already have.

Trade-offs

  • The most useful of the three, and the most work.
  • The window grows to about 900 px wide.
  • Shows more than you need for a quick app launch. Worth it if you search for files more often than you launch apps.
